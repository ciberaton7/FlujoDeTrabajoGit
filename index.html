Guía visual para el proyecto "Arena de Mitos y Leyendas"

                flowchart TD
                    subgraph Fase1 ["FASE 1: Preparación (Se hace UNA SOLA VEZ)"]
                        direction TB
                        A["1. Docente crea proyecto en Visual Studio"] --> B("2. Docente sube código a GitHub (Rama 'main')")
                        B --> C["3. Estudiante hace FORK (Copia en su cuenta web)"]

                    subgraph Fase2 ["FASE 2: Trabajo Diario (Se repite siempre)"]
                        direction TB
                        D --> E[["5. Estudiante crea RAMA / BRANCH (Ej: 'rama-duende')"]]
                        E --> F("6. Estudiante PROGRAMA (Crea sus clases)")
                        F --> G[["7. Estudiante hace COMMIT (Guarda localmente)"]]
                        G --> H[["8. Estudiante hace PUSH (Sube a SU nube)"]]
                        H -.->|"Si hay errores locales"| F
                    end

                    subgraph Fase3 ["FASE 3: Revisión e Integración"]
                        direction TB
                        H --> I["9. Estudiante presiona en la web: COMPARE & PULL REQUEST"]
                        I --> J("10. Estudiante crea el PULL REQUEST (Avisa al Docente)")
                        J --> K{"11. Docente Revisa"}
                        K -->|"Rechazado"| L["Docente pide correcciones"]
                        L -.->|"Estudiante corrige"| F
                        K -->|"Aprobado!"| M[["12. Docente hace MERGE PULL REQUEST"]]
                        M --> N((("Código integrado a la rama 'main' original")))
                    end

Glosario de Términos (Para Estudiantes)

Main (o Master)
Es la línea de tiempo principal y oficial del proyecto. Es el "trabajo en limpio". Regla de oro: Nunca se programa directamente en el Main.
Fork (Bifurcar)
Acción en la web de GitHub. Consiste en sacarle una fotocopia exacta al proyecto del docente y guardarla en tu propia cuenta de GitHub para que puedas modificarla sin pedir permiso.
Branch (Rama)
Es crear un "universo paralelo" dentro de tu proyecto. Te permite hacer experimentos o crear tus clases de forma aislada. Si lo arruinas, la rama principal sigue intacta.
Commit (Guardar Localmente)
Es como el "Guardar Partida" en un videojuego, pero requiere un título (ej. "Se agregó el método Atacar"). Guarda el progreso solo en tu computadora.
Push (Empujar)
Es la acción de subir todos tus "Guardados" (Commits) desde tu computadora hacia tu nube en GitHub.
Pull Request (PR)
Es una solicitud formal al dueño del proyecto original. Le estás diciendo: "Profe, terminé mi parte, revise mi código y únalo al juego principal".
Merge Pull Request
Es el botón definitivo que presiona el Líder/Docente. Aprueba tu solicitud y tu código pasa a formar parte oficial del proyecto general de la clase.
